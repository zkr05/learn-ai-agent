## D01 2026-10-08 ｜ 两数之和（数组 / 哈希） ｜ LeetCode 1 ｜ 简单

**思路**：
读懂约束 —— 题目保证每种输入只对应一个答案、同一元素不能重复使用，所以只要返回一对下标即可，
不用处理多解。
算法（暴力解）：双重循环枚举所有下标对 (i, j)，i < j，检查 nums[i] + nums[j] == target。
算法（优化版）：一边遍历一边查 —— 用字典记住「见过的值 -> 它的下标」；
每次查 target - x 在不在字典里，在就直接返回两个下标。

**卡点**：
动手前想了约 10 分钟，开始写之后就比较流畅，没有真正卡住。
唯一想了一下才定下来的：内层循环 j 要从 i+1 开始 —— 因为 i 之前的都已经遍历过了。

**复杂度**：
· 暴力解：时间 O(n^2) ／ 空间 O(1)
  （两层循环各自最多走 n 次 → 相乘得 n^2；只用了两个下标变量 → 空间常数）
· 优化版：时间 O(n) ／ 空间 O(n)
  （外层只走 n 次；字典的 in 查找和赋值插入都是 O(1) → 整体 O(n)。
    空间要额外存字典，最多 n 个元素 —— 本质是「用空间换时间」）

**下次注意**：
1. 遇到「找两个数满足某条件」这类题：**先写暴力解，然后问自己「哪一步在重复扫描」**。
   如果那一步是**查找**，就换成哈希表 —— 把 O(n) 的查找降成 O(1)，用空间换时间。
2. **必须先查再存**。反过来（先 `idx[x] = j` 再查）的话，`[3, 3]` 会返回 `[0, 0]`
   —— 同一个元素被用了两次，违反「同一元素不能重复使用」的约束。
3. **为什么用字典 `{}` 而不是 `set()`** —— 因为题目要返回**下标**，不是值。
   `set` 只能记住"这个值出现过"；`dict` 能记住"值 → 它在哪"。
   规则：**只判断存在性 → `set` 就够（还更省内存）；需要"值 → 附带信息"的映射 → 用 `dict`**。
   （对比：LeetCode 217「存在重复元素」只问有没有重复，用 `set` 就够了。）
4. 写优化版的时候别忘了给新函数加 assert —— 不然又是个没验证过的函数。

**状态**：完成（暴力解 + 优化版都通过）→ 复习D3 待做

## D02 2026-10-09 ｜ 字母异位词分组（哈希） ｜ LeetCode 49 ｜ 中等

**思路**：
抓住「异位词」的定义 —— 字母构成相同的词。把它们各自排序后，**字母的排列顺序这个无关差异被抹掉**，
只剩下「有哪些字母」，所以排序后的字符串能当分组依据。
用字典：key = 排序后的字符串，value = 该组的原词列表。

**卡点**：
一开始卡在「排序之后怎么回到原来的值」—— 我能把每个词排序得到指纹，但排序之后原词就丢了，
不知道该怎么把原词收进对应的组里。
后来想通：**指纹和原值是两个不同的东西** —— 指纹只用来「找到属于哪一组」，
而原词要自己另外存下来，那才是答案。字典的作用就是把「指纹 -> 原词列表」关联起来。

（推广：这类「按某个特征分组」的问题，结构是固定的 ——
  key = 特征（指纹），value = 属于这一组的原值列表。两者分开，缺一不可。）

**复杂度**：时间 O(n · k log k) ／ 空间 O(n · k)
（n = 单词个数，k = 单词最大长度。每个词排序是 O(k log k)，n 个词相乘；
  **不能只写 O(n)** —— k 是变量，不能当常数省略）

**下次注意**：
1. 哈希题选 key 的通用思路：**key 要代表「你想归成一类」的那个特征，并抹掉无关差异**。
   这题里无关的是「字母的排列顺序」，所以用排序抹掉。
2. **key 必须可哈希**：`list` / `dict` 不能当字典的 key，要转成 `tuple`。
3. 分组类问题可以 `from collections import defaultdict` + `defaultdict(list)`，
   省掉「key 不存在就建空列表」的三行判断。
4. **这题的断言不能直接比列表** —— 组内顺序和组间顺序都不保证，要先把每组排序、
   再把所有组排序（归一化）之后再比。
5. 进阶：用「字母计数元组」当 key 可以省掉排序，复杂度从 O(n·k log k) 降到 O(n·k)。

**状态**：完成 ｜ 复习D3 待做

## D03 2026-10-10 ｜ 最长连续序列（哈希） ｜ LeetCode 128 ｜ 中等

**思路**：
题目要求 O(n)，这一步直接**排除了排序**（排序是 O(n log n)）—— 最容易想到的解法进不来。
所以先把数组丢进 `set` 拿到 O(1) 查找，再找**连续段的起点**（`x-1` 不在 set 里），
从起点往后数到数不动为止。

**卡点**：
「要求 O(n) → 不能用排序 → 用哈希」这一步想通了，但**「while 只针对起点」一开始没想到**。
我最初的想法是每个数都往后数一遍 —— 那还是 O(n²)。
想通的关键：**每个连续段只该被数一次，所以只能从它的起点出发**。

**复杂度**：时间 O(n) ／ 空间 O(n)
这道题真正的考点是**均摊分析**（不是「用了哈希所以是 O(n)」）：
外层 n 次循环每次只做 O(1) 判断；`while` **只在起点执行**，
而每个数只属于一个连续段，所以 Σ(段长) ≤ n —— `while` 的**总**迭代次数 ≤ n。
所以是 n + n = O(n)，**不是** n × n。

**下次注意**：
1. 看到「要求 O(n)」先反推：**哪些常见解法的复杂度进不来**。
   这题排除排序 O(n log n) → 必须靠哈希把「查找」降成 O(1)。
2. **有嵌套循环不等于 O(n²)** —— 要看内层循环**总共**跑多少次，而不是单次上界。
   这是均摊分析，后面滑动窗口、单调栈还是同一个思想。
3. **「答案对」和「复杂度对」是两件独立的事。** 实测：保留 `continue` 但改成遍历 `nums`（有重复起点），
   答案照样正确，但 n=2000 时慢了 **377 倍** —— 重复的起点被反复数了一个完整段。
4. 数连续段用**半开区间**：`y` 停在第一个不在集合里的数，所以长度是 `y - x`，**不要写 `y - x + 1`**
   （和 `range(1, 4)` 是同一套约定）。
5. **初始值的选择决定要不要写边界特判**：`ans = 0` 恰好等于空数组的正确答案，
   所以不用写 `if not nums: return 0`。

**状态**：完成 ｜ 复习D3 待做

## D04 2026-10-12 ｜ 移动零（双指针） ｜ LeetCode 283 ｜ 简单

**思路**：
双指针。`start0` 指向「下一个非零元素该放的位置」—— 它同时等于「已处理区里非零元素的个数」。
一遍遍历：遇到非零就和 `nums[start0]` 交换，然后 `start0 += 1`。
扫完后 `[0, start0)` 全是非零（相对顺序天然保持），`[start0, n)` 全是 0。

**卡点**：没有卡很久，想通了不难。

**两条自述的批改**（答案都对，各有一处**归因**不准）：
1. 「必须交换是因为题目要求不能新建数组」—— 结论对（会丢数据），归因要拧一下。
   真正的原因是：**原地写入会覆盖掉原来的值，被覆盖的那个 0 必须有个去处**。
   交换就是把它安置到 `i` 位置 —— **0 的个数守恒**。
   （反过来说：如果允许新建数组，压根不需要交换 —— 直接搬非零再补零就行。
     所以"不能新建数组"是**约束**，不是"必须交换"的**原因**。）
2. 「空间是 O(1) 因为只存储了 nums」—— 答案对，理由错。空间复杂度算的是**额外空间**，
   `nums` 是输入、不算。真正的理由是只用 `start0` / `i` 两个下标变量。

**易错点（实测对照）**：写成 `nums[start0] = nums[i]`（不换回来）会把 0 直接销毁：
```
交换：  [0,1] -> [1,0]   正确
只赋值：[0,1] -> [1,1]   错误（0 的个数从 1 变成 0）
```
附带的优雅之处：`start0 == i`（还没遇到过 0）时，交换是「自己和自己换」，天然空操作，
不用额外加 `if i != start0`。

**复杂度**：时间 O(n) ／ 空间 O(1)

**下次注意**：
1. 双指针题的通用套路：**一个指针维护「已整理好的区域」的边界，另一个指针负责扫描**。
   这题的 `start0` 就是「已整理区」的右边界。
2. 「必须交换」的直觉应该来自**不变量**：这题的不变量是「0 的个数不变」。
   凡是原地修改，写下标之前先问一句：**我覆盖掉的那个值去哪了？**
3. 不要求相对顺序时，有**两端夹逼**的写法（左找 0、右找非零，交换）。实测交换次数：
   n=1000 随机输入下是 746 vs 196，**但最坏情况（一半 0 全在左边）两者相同（500 vs 500）**。
   所以它是**省常数**，不是**降复杂度** —— 而且代价是丢掉了相对顺序，不是白拿的。
4. 空间复杂度只算**额外**空间，输入本身不计入。

**状态**：完成 ｜ 复习D3 待做

## D05 2026-10-13 ｜ 盛最多水的容器（双指针） ｜ LeetCode 11 ｜ 中等

**思路**：
双指针从两端向中间夹逼，每轮算面积，然后**只移动矮的那一边**。
正确性靠**排除法**证明（不是"我觉得对"）：设 `h[left] < h[right]`，则
```
面积(left,k) = min(h[left],h[k]) * (k-left)
             <= h[left] * (k-left)       因为 min <= h[left]
             <  h[left] * (right-left)   因为 k < right
             =  当前面积
```
→ `left` 与其他任何更靠内的 `k` 组成的容器都不可能更优，**已被榨干，可以安全丢弃**。
机制一句话：**矮边封死了高度上限，想更优只能靠变宽，而宽度只会变小。**

**卡点**：没想到要移动短的那一边。看了题解有思路后就写出来了，总共约 25 分钟。

**复杂度**：时间 O(n) ／ 空间 O(1)
O(n) 的论证是**窗口单调收缩**：每轮必移动一个指针，窗口长度严格减 1，
从 n 收到 1 → 最多 n-1 轮（实测 n=50 → 49 轮）。
⚠️ 和 D03 的 O(n) **机制不同**：
- D03（最长连续序列）：**计数论证** —— `while` 只在起点进，每个元素最多被数一次，总迭代 ≤ n
- D05（本题）：**窗口收缩论证** —— 每轮消灭一个候选，轮数 ≤ n-1
两者同属**均摊分析**，但一个是「每个元素只被计一次」，一个是「每轮消灭一个候选」。

**实测反例（穷举搜出来的最小反例）**：
```
无脑移左边    [3,3,1]  正确=3, 错法=2   <- 它只走过 (0,2)、(1,2)，丢掉了最优的 (0,1)
移动高的一边  [1,3,3]  正确=3, 错法=2
2000 组随机输入：无脑移左边错 770 次(38.5%)、移高边错 1272 次(63.6%)
```

**下次注意**：
1. **双指针的正确性永远靠「排除法」证明**：不是"我找到了最优解"，
   而是"我证明了被丢掉的组合不可能更优"。说不出这句话，就是还没懂。
2. 两边相等时可以丢任意一边 —— 因为此时两边都是"矮边"，丢哪边都安全（对称）。
3. **发现自己举的例子不对，就去找一个真的**。我随手举的 `[1,8,6,2,5,4,8,3,7]`
   当反例是错的（它的最优组合恰好在「无脑移左边」的路径上），穷举才找到真正的最小反例 `[3,3,1]`。
4. **「答得出是什么，答不出为什么」是这周反复出现的短板**：
   - D02：「用了排序，复杂度就不是 n 了」（没说什么式子、为什么）
   - D03：「先找起点再 while，看着像嵌套但不是」（机制对，缺计数论证）
   - D05：「决定面积的是短边」（这是结论，不是论证）
   动作：**每写完一题自问「我这个做法为什么不会漏掉最优解？」—— 答出这句就是论证。**

## 复习4（D04 的第 3 天复习） 2026-10-14 ｜ 移动零 ｜ LeetCode 283

**结果**：独立重写成功，6 条断言一次通过（含 `[0,1]` 那个能抓出「只赋值不交换」的用例）。

**三段式首次落地** —— 今天刚把它加进每日流程（`algo/README.md`），这是第一次真填。两次填法的对比：

| 段 | 第 1 次填的 | 补全后 |
|---|---|---|
| ① 瓶颈 | `nums[start0]` | 同（**这段一次就对**，直接点到会被覆盖的那个位置，不是"指针"也不是 `i`） |
| ② 排除 | 「每次 `nums[start0]` 都是指向 0 元素，安全调用」 | 加了「遇到非 0 时，会将 0 与 `nums[i]` 交换」 |
| ③ 结论 | 「所以每轮可以放心交换推进 start0」 | 同 |

**这次真正的收获 —— 「观察」和「机制」的区分**：

> 「**是 0**」是**观察**；「**那个 0 的去处**」才是**机制**。

**反证（实测，这条要记住）**：**「`nums[start0]` 是 0」在错误版本里也成立。**
只赋值不交换时，`[0,1]` 每轮被覆盖的确实是 0 ——
```
第1轮: 覆盖前 nums[start0=0] = 0 ← 确实是 0
结果: [1, 1]   期望 [1, 0]  -> 错的
```
所以「是 0」**不是**安全的理由。理由是被覆盖的那个 0 **被交换安置到了 `i`**，于是 **0 的个数守恒**（不变量）。

**「排除」要写到凭据，不是写到观察**：
面试官不会问「被覆盖的是不是 0」（这他自己看得见），他会问「**凭什么说它一定是 0**」。
完整版长这样：

> 扫到 `i` 时 `nums[start0]` **一定是 0**（`[0,start0)` 全是已放好的非零、`[start0,i)` 全被判为 0）；
> 覆盖它 = 销毁这个 0，而交换把它安置到 `i` → **0 的个数守恒** → 答案不可能被丢。

**状态**：完成 ｜ 下次复习（D7）：2026-10-18

## D09 2026-10-20 ｜ 找到字符串中所有字母异位词（固定长度滑动窗口） ｜ LeetCode 438 ｜ 中等 ｜ 滑动窗口最后一题

**思路**：这题是 D02 的滑窗版。和 D08 的关键区别：

- **D09 固定长度窗口**：长度恒为 `len(p)` —— **右进一个、左出一个**

两件事让它做到 O(n)：
1. **增量更新**：窗口右滑一格只改两个字符的计数（进一个、出一个），O(1)。

   也是这题要消灭的东西。
2. **增量比较**：`cnt_p == cnt_s`。Counter 有自己的 `__eq__`，**计数为 0 的键视为不存在**
   （实测 `Counter(a=1) == Counter(a=1, b=0)` -> True；`Counter.__eq__` 确实不是 `dict.__eq__`）。

**复杂度**：时间 O(n)（每步 O(1) 更新 + 比较 O(|字符集|)，字符集是常数）；空间 O(|字符集|)。

**卡点**：卡在「左边的窗口要怎么缩短」。约 40 分钟。

⚠️ **这跟 D08 是同一个洞**：
- D08：「卡在怎么移动窗口的左边」
- D09：「卡在左边的窗口要怎么缩短」

两次卡的都是**左边界**。而这恰好就是「排除」那个问题：
> **左边界能动到哪里，等于你能证明「丢掉左边那部分不会漏」。**
> - D08：丢掉 `left' <= pos` 是安全的，因为它们**根本不合法**（含重复）
> - D09：丢掉左边那个是安全的，因为窗口**长度必须恰好 = len(p)**，多一个就不是候选

所以「左边界怎么动」和「三段式的排除」是**同一个问题的两种问法**。

## D10 2026-10-21 ｜ 和为 K 的子数组（前缀和 + 哈希） ｜ LeetCode 560 ｜ 中等 ｜ 子串第 1 题

**思路**：这题本质上就是 **D01 两数之和**，只是把「数」换成了「前缀和」。

```
sum(i..j) = prefix[j] - prefix[i-1]
=> 找 sum(i..j) == k  <=>  找 prefix[i-1] == prefix[j] - k
=> 扫到 j 时问：之前出现过几次 (prefix[j] - k)？   ← 这就是两数之和
```

| | D01 两数之和 | D10 和为 K 的子数组 |
|---|---|---|
| 在找什么 | `nums[i] == target - nums[j]` | `prefix[i-1] == prefix[j] - k` |
| 哈希里存什么 | 见过的**数** -> 下标 | 见过的**前缀和** -> 出现次数 |
| 先查再存 | ✅ | ✅（同一个坑） |

**卡点**：卡在「从 O(n^2) 暴力优化到 O(n)」。**优化是两步，不是一步**：
1. **前缀和**：消灭「重复累加」——暴力里固定 i 后，每个 j 都要把 i..j 重新加一遍
2. **哈希**：消灭「查找」——找 `prefix[i-1]` 从 O(n) 降到 O(1)

我当时只想到第 2 步（"内层循环用哈希"），但没说出第 1 步「重复加的是什么」。

**Q2 `cnt[0] = 1`（我答的是例子，不是理由）**
`cnt` 记录「已经出现过的前缀和」，`cnt[0]` 代表**空前缀**（下标 -1 处，和为 0）。
当 `s == k` 时 `s - k == 0`，需要 `cnt[0]` 才能数到「**从下标 0 开始**」的那个子数组。
实测去掉它：[1,1,1] k=2 少 1；[3] k=3 全丢。

**Q3 为什么不能用滑动窗口 —— 答对了** ✅
数组有负数 -> 窗口和不再单调 -> 「和太大就缩左边」的假设失效。
实测：`[1,-1,1] k=1` 滑窗得 2（正确 3）；`[1,-1,0] k=0` 滑窗得 1（正确 3）。

**Q4 先查再存 —— 答对了** ✅
先 `cnt[s] += 1` 再 `ans += cnt[s-k]`，k == 0 时会把当前前缀自己算进去（等于把空子数组当答案）。
实测：`[0,0,0] k=0` 返回 9（正确 6）；`[1] k=0` 返回 1（正确 0）。

**下次注意**：
1. **优化分两步**：先想「重复计算的是什么」-> 消灭它；再想「查找慢」-> 用哈希降。只做第二步会说不清为什么能到 O(n)。
2. 识别旧模式：这题 = D01 + 前缀和。**做新题时先问「它像我做过的哪一题」**，能省一半时间。
3. 「举一个反例」和「说清为什么」是两件事（Q2 就停在了反例上）。

## D11 2026-10-22 ｜ 滑动窗口最大值（单调队列） ｜ LeetCode 239 ｜ 困难 ｜ 子串第 2 题

**思路**：维护一个**下标双端队列**，元素满足「值单调递减 + 下标单调递增」-> 队首就是窗口最大值。

**两端各管一件事（这题最容易混的点）**：
| 端 | 删谁 | 管什么 |
|---|---|---|
| **队首（左）** | 已经**过期**的（下标 < `i-k+1`） | **时间** |
| **队尾（右）** | 值 `<=` 新元素的（被支配） | **能力** |

**为什么弹队尾是安全的（排除论证）**：
> 新来 `x` 在下标 `i`，队尾 `y` 在下标 `j`（`j < i`）且 `y <= x`。
> 对**任意**包含 `y` 的窗口：只要 `y` 还在，`x` 也一定在（`i > j`，`x` 更晚过期），
> 而 `x >= y` -> 那个窗口的最大值不可能是 `y`。
> => `y` 被 `x` 完全支配 -> 可以安全丢弃。

**卡点**：看不懂队首/队尾的进出。看了题解。**用轨迹表手动模拟一遍之后就通了** ——
`[1,3,-1,-3,5,3,6,7]` k=3，第 4 步（窗口滑到 `[-1,-3,5]`）一口气做了「队首过期 1 个 + 队尾淘汰 2 个」，
队列从 `[3,-1,-3]` 直接变成 `[5]` —— 这一幕把两端的分工说尽了。

**这版跟标准解不一样的两处，都验过是对的**：
1. **顺序反过来**（先队尾淘汰、再队首过期）：也对。因为**过期元素只可能出现在队首**
   （下标递增），而队尾淘汰只按「值」删，互不干扰。实测 5000 组结果一致。
2. **队首用 `if` 而不是 `while`**：也对。每轮 `left` 只前进 1 格、下标唯一
   -> 每轮**最多 1 个**过期（实测 5000 组，同一时刻最多 1 个）。

**⚠️ 这和 D08 正好相反，判据要记牢**：
- D08 必须 `while`：一轮里可能**连续**缩好几次（上一个重复字符可能隔着好几个字符）
- D11 用 `if` 就够：一轮里**最多**缩 1 个

判据永远是那句：**一轮里可能需要多次收缩吗？**

**复杂度**：时间 O(n)（每个下标最多入队一次、出队一次 -> 总操作 <= 2n）；空间 O(k)。
