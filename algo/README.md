# 算法练习

> 目的：实习笔试。**每天 1 道新题**；每题在第 3 天和第 7 天**额外**重写一遍
> （**复习不占新题的名额** —— 复习日一样要做当天的新题）。
> 难度从 Easy 起步，已逐步进 Medium。按小节顺序推进，不跳：哈希 → 双指针 → 滑动窗口 → 子串 → 普通数组 → 矩阵。

## 每天的流程

```
① 自己想 15 分钟（想不出很正常，别硬耗）
② 看题解，看懂为止
③ 【关键】关掉题解，自己从头写一遍 —— 写不出来就再看，直到能独立写出来
④ 填 notes.md（思路 / 卡点 / **证明三段式** / 下次注意）
⑤ 提交（用上面的格式）
```

**第 ③ 步不能省**，它就是"看懂"和"会写"之间的那道坎。

## 怎么答「为什么这么做」—— 证明三段式

刷题最容易停在这一层：**知道怎么做，说不清为什么对**。
D05（盛最多水的容器）就是这样 —— 能写出「移动矮的那边」，但说不出「为什么不会漏掉最优解」。
面试的差别全在这一步：说得出「排除」那一步 → 真懂；说不出 → **背题**（面试官一追问就露）。

**三段式**（双指针 / 贪心 / 滑窗 都适用）：

1. **找瓶颈** —— 当前窗口里，是哪一边限制了结果？
2. **排除** —— 证明「丢掉这个瓶颈之后，剩下的组合里不可能有更优解」（用不等式或计数）
3. **结论** —— 所以移动指针是安全的

> 自查问句：**我这个做法为什么不会漏掉最优解？**

**做过的题各自怎么答：**

| 题 | 瓶颈 | 排除（关键那一句） |
|---|---|---|
| D03 最长连续序列 | 连续段的起点 | 只有起点能开启新段，非起点都被前一个元素包含了 → `while` 只在起点进，每个元素最多被数一次 |
| D04 移动零 | 被覆盖的位置 | 原地写入会覆盖旧值，**0 的个数必须守恒** → 所以必须交换，把 0 安置到 `i` |
| D05 盛最多水的容器 | 矮的那条边 | 矮边封死了高度上限，想更优只能靠变宽，而宽度只会变小 → 矮边可以安全丢弃 |
| D05（两边相等时） | 两边都是瓶颈 | 对称 → 丢哪边都安全 |

**两道题的 O(n) 论证机制并不相同**（别把它们当成同一个）：

- **D03**：**计数论证** —— `while` 只在起点进，总迭代 ≤ n
- **D05**：**窗口收缩论证** —— 每轮必消灭一个候选，轮数 ≤ n−1
